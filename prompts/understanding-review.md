# Module: Understanding Review

Run after the scientific review. Goal: remove what does not help, add what is missing for comprehension. Never remove uncertainty or assumptions to reduce length.

## Questions

1. Is text used where a diagram would show the structure faster?
2. Is a static figure used where interaction would reveal the sensitivity?
3. Is an animation used where a plot is enough? (Animation for animation's sake.)
4. Are there too many representations? Does each answer a question the others do not? (Visualization overload.)
5. Is any information increasing load without serving the question? Move it to a "details" layer or remove it.
6. Is the sequence logical: intuition → mechanism → quantification → sensitivity → limits?
7. Can the user see **why** the result occurs, not just what it is?
8. Can the user find assumptions and uncertainty in under 10 seconds?
9. Is every equation followed by its physical meaning? (Equation dumping.)
10. Is an HTML page mostly prose? (HTML textbook.)
11. Does depth match the user's stated expertise? Expert: plain language, full content. Beginner: fewer layers, not wrong content.
12. Language: user's language for explanation; English technical terms kept per SKILL.md rules; one term per concept throughout.
13. Does the Representation Decision block match what was actually delivered?

## Action

For each "no" or "too much": change the artifact, then re-run the scientific review on changed parts.
